# TOS-Korea: 대한민국 온라인 서비스 약관 변경 이력

> **최신성 안내:** 각 서비스의 자동화된 약관 확인·수집 허용 여부가 확인되지 않아, 이 저장소는 정기적인 자동 수집을 운영하지 않습니다. **최신 버전의 수록이나 지속적인 갱신을 보장하지 않습니다.** 현재 유효한 약관은 각 서비스 제공자의 공식 웹사이트에서 확인해 주세요.
>
> **쿠팡:** 2026-10-02 쿠팡 회신에 따라 자동화된 수집이 약관(쿠팡 이용 약관 제12조 제2항 제4호)상 허용되지 않음을 확인하여, **쿠팡 약관은 정기적으로 갱신하지 않습니다.** 자세한 내용은 [`docs/coupang/README.md`](docs/coupang/README.md#정기-갱신-중단)에 있습니다.
>
> **넥슨:** 2026-10-08 넥슨 회신에 따라 자동화된 수단을 통한 수집이 허용 범위가 아님을 확인하여, **넥슨 약관은 정기적으로 갱신하지 않습니다.** 넥슨 수록본은 비공식 자료이며 넥슨이 승인하거나 협력하는 프로젝트가 아닙니다. 넥슨은 그 정확성·최신성을 보증하지 않으며, 적용되는 약관은 넥슨 공식 페이지에 게시된 해당 시점의 약관을 기준으로 확인해야 합니다. 자세한 내용은 [`docs/nexon/mabinogimobile.md`](docs/nexon/mabinogimobile.md#정기-갱신-중단과-표시고지)에 있습니다.

대한민국 온라인 서비스 이용약관과 정책이 **언제, 어떻게 바뀌었는지** 추적하고 비교하기 위한 역사적 기록(historical record)입니다. 약관 파일 하나가 문서이고, 커밋 하나가 그 문서의 한 버전입니다.

| | |
|---|---|
| **목적** (Purpose) | 공개된 온라인 서비스 약관의 과거 변경 이력을 추적하고 비교합니다.<br>*Tracking and comparing historical changes in publicly accessible online Terms of Service.* |
| **출처** (Source) | 누구나 볼 수 있게 공개된 페이지, 주로 각 서비스 제공자의 공식 페이지에서 수집했습니다.<br>*Terms are collected from publicly accessible sources, primarily official service-provider pages.* |
| **권리** (Rights) | 저작권과 그 밖의 권리는 각 권리자에게 있습니다.<br>*Copyright and other rights remain with their respective rights holders.* |
| **정본** (Canonical Source) | 현재 유효한 약관의 기준은 각 서비스 제공자의 공식 웹사이트입니다.<br>*The official website of each service provider remains the authoritative source for the current Terms of Service.* |

## 1. 프로젝트 개요

- 대한민국 온라인 서비스의 이용약관, 운영정책, 개인정보 처리방침 등을 **버전별로 보존**하고, Git의 history와 diff로 **변경 시점과 변경 내용**을 확인할 수 있게 합니다.
- 이 저장소는 약관을 대신 제공하거나 공식 약관 제공 서비스를 만드는 것이 목적이 아닙니다. 파일은 공식 약관의 대체본이 아니라 **버전 추적용 기록**(historical / version-tracking record)입니다.
- 수집·비교 중 발견한 약관 데이터 오류는 사업자에게 제보하고 [`docs/ISSUES.md`](docs/ISSUES.md)에 기록합니다.
- [legalize-kr](https://legalize.kr) (대한민국 법령 Git 저장소)의 방식을 따릅니다.

```bash
git clone https://github.com/jinbumlee95/TOS-Korea-Project.git
cd TOS-Korea-Project

git log -- coupang/쿠팡이용약관.md                       # 한 약관의 개정 이력
git log -p -1 -- coupang/쿠팡이용약관.md                 # 직전 개정에서 바뀐 내용
git log -- tving/                                       # 회사 하나의 전체 변경 이력 (시간순)
git log --before="2025-01-01" -1 -- coupang/쿠팡이용약관.md  # 특정 날짜 당시의 버전
grep -r "개인정보" .                                     # 전체에서 단어 검색
```

Windows에서 한글 파일명이 깨져 보이면 `git config core.quotepath false`를 설정하세요.

## 2. 이 프로젝트가 있는 이유

약관은 개정되면 공식 페이지에서 새 버전으로 바뀌고, 과거 버전은 찾기 어렵거나 사라지는 경우가 많습니다. 이 프로젝트는 과거 버전을 기록으로 남겨, 어느 조항이 언제 어떻게 바뀌었는지 나중에도 확인하고 비교할 수 있게 하려고 만들었습니다.

**전체 문서를 보존하는 이유:** 변경을 찾으려면 비교할 두 버전이 모두 온전히 있어야 합니다.

*Full-text preservation is necessary to identify and compare changes between different versions of the Terms of Service.*

```text
버전 A 전문 ─┐
             ├─→ 조항 단위 비교 (diff) ─→ 추가·삭제·수정된 조항 식별
버전 B 전문 ─┘
```

요약이나 발췌만 남기면 무엇이 빠졌는지, 어떤 문구가 조용히 바뀌었는지 확인할 수 없습니다.

*All terms are sourced from publicly accessible official pages of the respective service providers.*

### 구조

```
{회사}/
  {약관명(띄어쓰기 제거)}.md

{게임사}/
  {게임}/
    {약관명(띄어쓰기 제거)}.md
    {약관명(띄어쓰기 제거)}({플랫폼}).md

docs/
  README.md                  # 기업별 문서 및 근거 안내
  ISSUES.md                  # 관찰 사항과 제보 현황
  {회사}/README.md           # 회사별 설명
  {회사}/evidence/{사례}/     # 원문 백업과 관찰 기록
  {게임사}/{게임}.md
```

- 회사·게임 디렉토리는 영문 소문자를 씁니다 (`coupang`, `navercloud`, `krafton/pubg`, `riotgames/leagueoflegends` 등). 문서가 많은 회사는 분류별 하위 폴더를 둡니다 (예: `navercloud/terms/`, `navercloud/sla/`).
- 파일명은 회사가 게시한 약관 제목에서 띄어쓰기를 뺀 것입니다. Windows에서 쓸 수 없는 문자(`:` 등)도 뺍니다.
- 게임사는 게임별로 약관이 따로 있어서 `{게임사}/{게임}/` 아래에 둡니다. 같은 약관이 플랫폼(Steam, PlayStation 등)별로 따로 게시되면 `{약관명}({플랫폼}).md`로 구분합니다.

### 메타데이터 (YAML Frontmatter)

모든 약관 파일은 출처와 날짜를 frontmatter에 적습니다.

```yaml
---
제목: 쿠팡 이용 약관
회사: 쿠팡
버전일자: 2026-09-04
시행일자: 2026-09-03
출처: https://www.coupang.com/np/policies/terms
수집일자: 2026-09-28
---
```

| 항목 | 필드 | 설명 |
|------|------|------|
| 회사·서비스명 | `회사`, `게임`, `플랫폼`, `서비스` | `게임`·`플랫폼`·`서비스`는 해당하는 회사에만 있음 |
| 약관명 | `제목` | 공식 페이지에 표시된 현재 제목 |
| 개정일 | `버전일자` | 사이트의 버전 목록("이전 버전 보기", 날짜 선택 등)에 표시된 날짜. 버전 목록이 없으면 본문에 적힌 게시일, 그것도 없으면 `null` |
| 시행일 | `시행일자` | 본문(부칙 등)에 명시된 시행일. "…부터 시행" 문장과 "시행일: …" 표시를 모두 봅니다. 본문에 없거나 버전일자와 60일 넘게 차이 나면 생략 |
| 원문 출처 | `출처` | 수집한 공식 페이지 주소 |
| 원문 판 | `판`, `원문PDF` | 원문이 PDF인 회사(네이버 클라우드 플랫폼)에만 있음 |
| 수집 날짜 | `수집일자` | 그 버전을 수집한 날짜. 과거 버전은 그 버전이 유효하던 날이 아니라 사이트의 과거 버전 페이지에서 받은 날입니다 |

**현재·과거 버전 구분:** 파일의 최신 커밋이 **저장소가 마지막으로 수집한 버전**이고, 그 이전 커밋들이 과거 버전입니다. 최신 커밋이라도 지금 유효한 버전이라는 보장은 없습니다. 수집 뒤에 개정되었을 수 있으니 현재 약관은 공식 페이지에서 확인하세요.

## 4. 버전 추적과 변경 비교

Git 커밋은 단순한 저장 이력이 아니라 다음을 위한 구조입니다.

- **버전별 보존:** 약관의 각 버전이 커밋 하나로 남습니다.
- **변경 시점 추적:** 커밋 날짜가 그 버전의 버전일자(정오, KST)입니다. `git log`가 곧 개정 연표입니다.
- **조항 변경 비교:** 두 커밋 사이의 `git diff`로 추가·삭제·수정된 조항과 문구를 확인합니다.

예시 (카카오계정 약관, 실제 이력):

```text
2026-05-29 버전
     ↓
2026-09-22 버전
     ↓
제 16 조 (손해배상) ② 변경
     ↓
"또한 회사는 법률상 허용되는 한도 내에서 간접 손해, …"
 → "또한 회사는 간접 손해, …"  ("법률상 허용되는 한도 내에서" 삭제)
```

```bash
git log --format="%h %ad %s" --date=short -- kakao/카카오계정약관.md
git diff --word-diff 1b515b7 aefaa15 -- kakao/카카오계정약관.md
```

### 커밋 규칙

약관 커밋은 버전일자(정오, KST)를 Git author/committer date로 씁니다. 커밋 메시지 형식:

```
쿠팡: 쿠팡 이용 약관 (개정)

원문: https://www.coupang.com/np/policies/terms

버전일자: 2026-09-04
시행일자: 2026-09-03
회사: 쿠팡
수집일자: 2026-09-28
```

개정 구분:
- `최초 수록`: 저장소에 처음 추가된 버전 (회사가 공개한 가장 오래된 버전이며, 실제 제정본이 아닐 수 있음)
- `개정`: 직전 버전과 본문이 다름
- `버전 갱신, 본문 동일`: 새 버전이 게시되었으나 본문은 같음 (파일 변경이 없으면 빈 커밋으로 기록)

같은 날짜에 커밋이 여러 개면 순서를 지키려고 12:00:00, 12:00:01, … 처럼 초를 늘립니다. 사이트 목록에 같은 날짜가 두 번 나오면 먼저 게시된 것을 먼저, 나중 것을 "같은 날짜의 두 번째 버전"으로 커밋합니다. 버전 정보가 없는 약관은 본문에 적힌 게시일·시행일로, 그것도 없으면 수집일자로 커밋하고 `docs/`의 회사별 설명 문서에 적어 둡니다.

### 커밋이 쌓이는 순서

커밋은 **회사 단위로** 쌓입니다. 새 회사를 수록할 때는 그 회사의 과거 버전을 날짜순으로 기존 히스토리 위에 쌓고, 이미 수록된 회사는 새로 나온 버전만 쌓습니다. 평소에는 기존 커밋을 다시 쓰지 않습니다.

**커밋 해시는 바뀔 수 있습니다.** 이미 수록한 버전의 메타데이터를 보충해야 할 때(예: 본문에 적힌 시행일을 `시행일자`로 채우는 경우) 히스토리를 다시 정립할 수 있고, 그러면 커밋 해시가 바뀝니다. 이때도 다음은 그대로 지킵니다.

- 약관 본문은 바꾸지 않고 frontmatter와 커밋 메시지의 메타데이터만 보충합니다.
- 커밋 날짜는 회사별 날짜 규칙(버전일자 정오 KST, 같은 날짜는 초를 늘림, 버전 정보가 없으면 본문 날짜 또는 수집일자)을 그대로 따르고, 회사 안의 커밋 순서도 그대로입니다.
- 버전을 가리킬 때는 커밋 해시보다 **파일 경로와 버전일자**를 쓰세요. 해시는 다시 정립되면 달라집니다.

다시 정립한 기록:

| 날짜 | 내용 |
|------|------|
| 2026-10-02 | 본문의 "시행일: …"·"시행일자 : …" 표시를 `시행일자`로 보충 (버전 318개, 카카오·네이버·라이엇게임즈·TVING·KT·넥슨). 이전에는 "…부터 시행" 문장만 읽어 빠졌습니다. 기존 `시행일자` 값은 바뀐 것이 없습니다 |

그래서 회사 안에서는 시간순이지만, 저장소 전체로 보면 회사가 추가된 순서대로 묶여 있습니다. 전체 `git log`에서는 나중에 수록한 회사의 2010년 커밋이 먼저 수록한 회사의 2026년 커밋보다 위에 나올 수 있습니다.

- 이력은 `git log -- {회사}/` 또는 `git log -- {회사}/{약관}.md`처럼 **경로를 지정**해서 보세요. 이렇게 보면 항상 시간순입니다.
- 경로 없이 저장소 전체에 `--since`를 쓰면 git이 탐색을 일찍 멈춰 일부 커밋이 빠질 수 있습니다. 날짜로 거를 때도 경로를 지정하세요.
- 파일을 바꾸지 않은 빈 커밋(`버전 갱신, 본문 동일`)은 경로를 지정한 `git log`에 나오지 않습니다. 모두 보려면 `git log --grep="TVING:"`처럼 커밋 메시지로 찾으세요.

### 약관 데이터 검증 과정에서 발견된 오류 및 제보

TOS-Korea는 이용약관의 변경 이력뿐 아니라, 수집·비교 과정에서 발견되는 약관 데이터의 오류나 버전 간 불일치도 확인하고 있습니다.

실제로 네이버 클라우드 플랫폼의 이용약관을 비교·검증하는 과정에서, 약관 페이지의 일부 판에 다른 문서의 원문이 연결된 오류를 발견하여 해당 기업에 제보하였고, 기업의 확인을 통해 해당 내용이 실제 오류임을 확인했습니다.

이를 통해 본 프로젝트의 약관 데이터 수집·비교가 단순한 데이터 축적을 넘어, 이용자가 확인하기 어려운 약관 정보의 오류를 발견하고 사업자에게 피드백하는 검증 기능으로도 활용될 수 있음을 확인했습니다.

제보 내역은 [`docs/ISSUES.md`](docs/ISSUES.md)에 사실관계 중심으로 기록합니다.

## 5. 데이터 및 저작권 귀속

- 수록된 이용약관, 운영정책, 개인정보 처리방침 등 문서의 **저작권과 그 밖의 권리는 해당 문서를 작성·게시한 권리자에게 있습니다.**

- 모든 문서는 frontmatter의 `출처`에 원문 페이지를, 커밋 메시지에 원문 주소를 적어 둡니다.
- 회사명, 서비스명, 상표는 각 권리자의 것입니다. 이 저장소는 어떤 기업과도 제휴하거나 승인받지 않았습니다.

## 6. 정본 (Canonical Source)

- 현재 유효한 약관의 최종적이고 공식적인 기준은 **각 서비스 제공자의 공식 약관 페이지**입니다.
- 이 저장소의 파일은 공식 약관의 대체본이 아니라, 공개 페이지를 수집해 Markdown으로 변환한 **버전 추적용 기록**입니다.
  - 제목(`#`), 장·부칙(`##`), 조 또는 번호 절(`###`) 외의 서식은 단순화했습니다. 표는 Markdown 표로, 번호 목록의 번호는 화면에 보이는 대로 글자로 옮겼습니다.
  - 변환 과정에서 서식이나 내용이 원문과 다를 수 있습니다.
  - 버전일자·시행일자는 수집 시점에 사이트에 표시된 정보를 바탕으로 정했습니다.

## 7. 수집 원칙과 방식

### 원칙

- 로그인 없이 누구나 볼 수 있게 공개된 페이지만 수집합니다.
- 약관 페이지(버전) 하나당 한 번씩 방문하고, 방문 사이에 간격을 둡니다.
- 본문 글자는 바꾸지 않습니다. 공백과 제목 표시 외에는 원문 그대로 둡니다.

### 방식

현재까지 수집은 모두 **관리자가 직접** 진행했습니다. 관리자가 수집할 회사를 정해 필요할 때 진행하며, 정해진 주기로 사이트를 계속 크롤링하는 자동 수집은 운영하지 않습니다. 회사마다 페이지 구조가 달라서 방법이 다르며, 회사별 수집 범위와 예외는 `docs/{회사}/README.md`에 있습니다.

1. **공개 페이지 확인:** 관리자가 공식 약관 페이지와 그 페이지가 제공하는 과거 버전 목록(버전 선택, "이전 버전 보기" 등)을 확인합니다.
2. **페이지 저장:** 각 버전의 페이지를 방문해 로컬에 저장합니다. 원문이 PDF로 게시된 경우(네이버 클라우드 플랫폼)에는 PDF를 저장합니다.
3. **파싱:** 저장한 페이지(HTML·PDF)를 파서로 변환해 본문, 장·조 제목, 버전일자·시행일자를 뽑습니다.
4. **기록:** 버전마다 커밋 하나로 이 저장소에 쌓습니다.
5. **비교:** 이후 변경 확인은 이 저장소의 history와 diff로 합니다. 비교 단계에서는 사이트에 요청하지 않습니다.

수집 방식이 바뀌면 이 절을 갱신합니다.
